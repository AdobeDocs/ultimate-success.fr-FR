# Sites rapides et modifiables avec éditeur universel et frameworks de rendu côté serveur modernes

Les équipes web modernes voulaient la liberté des frameworks JavaScript découplés et modernes sans sacrifier l’édition contextuelle pour les marketeurs. Au cours de cette session, nous avons montré comment l’éditeur universel de Adobe Experience Manager et les structures modernes de rendu côté serveur (telles que les configurations de style React et Next.js) fournissaient des sites rapides et optimisés pour les moteurs de recherche (SEO) que les auteurs pouvaient toujours modifier visuellement. Nous avons expliqué comment connecter l’éditeur universel à des applications basées sur un framework, comment le rendu côté serveur affectait les performances et Core Web Vitals, et comment structurer les composants afin que les créateurs et créatrices puissent mettre à jour les expériences en toute sécurité sans interrompre le front-end. Si vous planifiez ou modernisez un projet Adobe Experience Manager (AEM) ou Edge Delivery Services (EDS), ce webinaire vous a fourni un plan pratique que vous pouvez utiliser immédiatement.

>[!VIDEO](https://video.tv.adobe.com/v/3491408/?learn=on&enablevpops)

## Points essentiels à retenir

* **Quand utiliser un site EDS standard ou un framework SSR personnalisé ?**
Nous avons compris pourquoi un site Adobe Experience Manager Edge Delivery Services (EDS) standard était le meilleur site par défaut pour la plupart des projets et quand il était logique de superposer l’éditeur universel sur une application existante (comme une boutique ou un portail) au lieu de la reconstruire.

* **Comment l’éditeur universel est connecté à EDS et aux structures existantes**
Nous avons vu comment l’éditeur universel s’intègre dans une configuration AEM EDS standard et comment les mêmes concepts sont appliqués lors de sa connexion à une application de rendu côté serveur de style React ou Next.js déjà en production.

* **Le rendu côté serveur où il comptait équilibrer les paramètres par défaut des services EDS avec les performances et les besoins SEO**
Nous avons appris quand nous pouvions nous fier aux valeurs par défaut d’EDS et quand nous avions vraiment besoin d’un rendu côté serveur (SSR) personnalisé pour des expériences spécifiques, y compris l’impact sur l’optimisation du moteur de recherche (SEO) et Core Web Vitals pour les pages à forte valeur ajoutée telles que les détails de produit ou les pages de destination.

* **Création qui n’a pas interrompu les modèles de votre application pour les développeurs et les spécialistes marketing**
Nous avons découvert des modèles de composants et de modèles de contenu qui permettent aux développeurs de conserver une base de code propre et gérable tout en offrant aux auteurs une puissance de modification contextuelle sécurisée, que ce soit sur un site EDS standard ou intégré à un framework existant.
